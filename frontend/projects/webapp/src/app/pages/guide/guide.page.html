Fixing a file

How to read what the validator reports, correct your mzTab-M file in the browser, and take the corrected file with you.

Read a result and its guidance

Validate your file on the start page. The result lists what jmzTab-m found. Messages of the same kind are grouped, so a problem that repeats on many lines appears once, with a count.

Open a group to see its guidance. It says what the problem means, what to change in the tool that wrote the file, and what you can do here. Choose Show first → to see where the problem is.

The most frequent problems are explained on the Common problems page, with the steps for some tools.

To correct the file here, press Fix this file on the result page. On the start page, choose a file and press Open a file to fix; the editor opens when the result is ready.

Fix a file in place

The editor works on a copy of your upload. Your original is never changed. Everything you do is a change to the text of the copy, and the validator checks the text again; it does not guess what you meant.

Edit a value

Click a cell of a table, or a value in the metadata, and type. Press Enter to save the change. Press Escape to drop it. One edit can change one cell. A cell can hold up to 100,000 characters.

Fix a line the editor cannot show

A line that cannot be shown as metadata or as a table row opens in a text field with its raw text. Tabs are shown as →. Change the text and press Save line, or press Delete this line. A line can hold up to 1,000,000 characters.

Use a quick fix

For some problems the guidance offers a quick fix. You always see a before and after of every changed line first, and nothing changes until you press Apply. A quick fix never chooses a term, a unit or a value for you. These quick fixes exist:

  • remove an empty parameter
  • write a DOI as doi:10.xxxx/yyyy
  • join a line that was broken in two
  • split a metadata line whose key and value are separated by spaces instead of a tab
  • add a column that the file must have
  • add a missing metadata line, for you to fill in
  • remove a controlled vocabulary entry that nothing uses

Resolve a duplicate column

When a table has two columns with the same name, the column is marked dup. Choose Resolve duplicate column. You can keep one column and delete the others, or merge them into one column. A merge keeps the value of the column you choose in each row; where it is empty or null, the first other value that is neither is used. The dialog shows the rows whose values differ before you apply it.

You cannot rename a column to a name that another column already has, or insert one.

Undo and redo

Undo and Redo (Ctrl+Z and Ctrl+Shift+Z) step through your changes. The last 100 steps are kept, and a very large change may reduce that number. One batch of changes can hold up to 5,000 edits.

Checking your changes

After 1.5 seconds without a change, the editor checks the structure again and shows which problems are new and which are fixed. The mzTab-M version is read again from the text, so a change to the version line is picked up. The rules for controlled vocabulary terms are checked when you press Check CV rules, because they need the EBI Ontology Lookup Service and can take longer.

When jmzTab-m stops reading

If a line is broken badly enough, jmzTab-m cannot go on. The editor then says jmzTab-m stopped reading at line N. Only the problems above that line are reported, so more can appear once you fix it. This is why a short list of problems can grow after your first fix. Fix the line it names first. You can still read and edit the lines below it.

Downloads and the resolution report

  • Download .mzTab is the corrected file, exactly as it is in the editor.
  • Download JSON is offered once the file is checked without errors. It is made from the corrected text.
  • Download original is your upload, unchanged.
  • Download resolution report is a Markdown file named after your file, ending in -problems.md. It lists each problem with its explanation and how to fix it in your tool. You can send it to the person who produced the file, or keep it with your records.

Use the resolution report when the cause is in the tool that wrote the file. Fixing it only here would repeat the problem next time.

A change to the copy starts the time again. Anyone who has the address of the editor can open and change the file, so share it with care. You can delete a result earlier on its result page.

Files that are not UTF-8

mzTab-M files are UTF-8. If your file is not, the editor says so and names the first line with a character it cannot read. If your tool wrote the file as Windows-1252 or Latin-1, press Re-encode from Windows-1252. The corrected file is then UTF-8. Look at accented letters and symbols such as µ afterwards; if they look wrong, the file used a different encoding and should be exported again from your tool.
