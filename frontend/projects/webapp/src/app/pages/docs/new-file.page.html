Start an mzTab-M file from three choices, see what it still needs, and fill it from a vocabulary file or by hand.

The three choices

Choose New file in the app bar, or go to the new file page. The form asks for three things, and for the name of the file:

  • mzTab-M version. Only the versions this service can check are offered; the default is preselected. See mzTab-M 2.0 and 2.1.
  • Content profile. Asked for mzTab-M 2.1 only: M, M+S, M+F, M+F+E or M+S+F+E. It says which sections the file has. A 2.0 file has no content profile.
  • Repository rules. The validation profile the file is checked against, from the catalog. Only the profiles that list the chosen version are offered.
  • mzTab-ID. Letters, digits, dots, underscores and hyphens, starting with a letter or a digit, up to 64 characters. The file is named after it.

Create file opens the editor on the new file. Like any file in the editor, it is kept for a time after your last change (see Fixing a file), and anyone with the address of the editor can open and change it.

Why the new file is not valid yet

The new file holds only what you chose: its mzTab-version, its mzTab-ID and, for 2.1, its mzTab-profile. It is not a valid file, and the editor shows errors from the first moment. That is intended. A valid file needs facts nobody has given yet, such as the software, the assays, the polarity, the quantification method or the controlled vocabularies, and the service does not make them up.

The messages and the list called Still missing say what to add. Add it by hand, as described in Fixing a file, or from a vocabulary file.

Still missing

Still missing is shown for a new file only. It lists the rules of your repository rules that the file does not meet yet. It is decided from the text of the file, so it follows every change.

  • Required are the rules the repository demands (MUST).
  • Recommended are the rules it asks for (SHOULD).
  • When nothing is left, it says "Nothing is missing for these repository rules."
  • Not yet checked lists the rules while the file cannot be read into a model: "The file cannot be read into a model yet, so these rules could not be checked against it. Fix the errors in the messages first." A new file stays here until it has, at least, its software, assays and controlled vocabularies.

It lists rules, not values: it says that a rule is not met, and the messages say where. Nothing is filled in for you.

Add from a vocabulary file

The editor's panel Add from… fills the file from a file you already have. It is offered for mzTab-M 2.0 files; for 2.1 it says so.

  1. Press A vocabulary file (JSON).
  2. Choose the file. It is the JSON of the submission vocabulary: what its template reader writes, or what your tool writes. It can be at most 5 MiB.
  3. If the file has several datasets, choose the one this mzTab-M file is for.
  4. Check the Study id. It is prefilled from the file and the mzTab-ID is made from it, for example LCS-00123.
  5. Look at the preview. Nothing is changed in your file until you press Apply.

The preview

The preview lists each key and value that the import would write, with its state:

  • new: the file does not have it yet;
  • unchanged: the file has the same value;
  • kept (differs): the file has another value and keeps it;
  • replaces existing: the file has another value and the import replaces it.

The notes below the table say what the import could not map.

Keep existing values

Keep existing values is on by default. A value your file already has stays, and where the import differs it is listed as kept (differs). Turn it off, and the preview is made again, to let the import replace the values the file has where the import matches the element; other differing values stay as conflicts. The import is applied as a whole; single lines cannot be left out.

When the file changes meanwhile

A preview belongs to the file as it was. If you change the file afterwards, the panel says so and offers Preview again; Apply waits for it.

Undo

An import is one change. One Undo takes back everything it wrote and returns the file to the text it had before, and Redo applies it again.

After the import, the file is checked again. If errors remain, the messages and Still missing say what is left. For the next steps see Fixing a file.
