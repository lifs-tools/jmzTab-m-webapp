# mzTab-M Validator 2.0.0

## Highlights

- **New user interface.** The Thymeleaf pages are replaced by an Angular single-page application in the LIFS design: validator form with progress state, result page with messages, metadata, summary (SML), features (SMF) and evidence (SME) tabs, examples, About and not-found pages, retention notice, LIFS branding and Matomo with consent.
- **mzTab 1.0 is retired.** The validator handles mzTab-M 2.0 only. Use a 1.0.x release for mzTab 1.0 files.
- **Validation profiles and custom mapping files.** Choose a profile from the catalog (currently `mztab-m-2.0-default`) or upload your own CV mapping file (server option `validation.custom-mappings.enabled`).
- **Results persist.** Results are stored on disk for the retention period (`minCleanupAge`, 7 days by default) and survive restarts and redeploys. A storage cap (`storage.max-total-bytes`) refuses new validations when reached.
- **Large files.** The result page pages through tables on the server (checked with a 31 MB file whose SML table has 846 rows by 1,989 columns); the browser never receives a whole table.

## REST API

- `POST /rest/v2/validate` and `POST /rest/v2/validatePlain` are **unchanged** (including the `semanticValidation=false` default). `/convert` and `/convertPlain` are untouched.
- New endpoints under `/rest/v2`:
  - `POST /validations` (multipart; level, max errors, semantic validation, profile, custom mapping file) starts an asynchronous validation;
  - `GET /validations/{id}` status and messages; `DELETE /validations/{id}` deletes the result;
  - `GET /validations/{id}/report` downloads the report;
  - `GET /validations/{id}/metadata` and `/metadata/{group}` read the metadata groups;
  - `GET /validations/{id}/tables/{section}` (sml, smf, sme) with `page`, `size`, `sort`, `descending`, `columns` and `filter`;
  - `GET /validation-profiles` lists the validation profiles;
  - `GET /examples` lists examples; `POST /examples/{id}/validations` validates one;
  - `GET /app-info` version, build, retention, upload limit and analytics settings.
- Errors under `/rest/**` are JSON.

## Upgrade notes

- **One replica per instance.** Results live on the instance's local storage. The production stack goes from two replicas to one.
- **Mount a volume at `storage.location`** (default `${java.io.tmpdir}/upload-dir`, i.e. `/tmp/upload-dir` in the Docker image) to keep results across redeploys. No environment changes are required for the existing compose files.
- Server-side analytics events are anonymous. Browser analytics (Matomo) load only if `ga.id` is set and only after consent.
- Old URLs keep working: `/validate/{id}` redirects to `/result/{id}`; `/validate/{id}/delete` opens the result page with the delete confirmation (it never deletes on GET).
- The Docker image is published as `lifs/mztab-validator-webapp`.
- The Thymeleaf, jQuery, Bootstrap and mzTab 1.0 dependencies are removed.

## Known limitations

- The LIFS brand colour contrast on some elements is pending a design decision.
- There is no end-to-end test that validates an example live (examples are fetched from GitHub).
